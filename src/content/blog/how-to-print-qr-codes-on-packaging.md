A QR code on a package is only useful if it scans. A code that looks fine to the eye but fails on a customer's phone — or on a warehouse scanner — is worse than no code at all: it breaks traceability, blocks a promotion, and in regulated markets it can hold up a whole shipment. The good news is that scannable QR codes are not hard to print. They fail for a small set of repeatable reasons, and every one of them is avoidable if you pick the right printer and follow a few rules.

## What printer do you need for QR codes?

A QR code is variable data — a grid of tiny black and white squares that changes with every product, batch or serial number. That rules out the fixed-type machines: ribbon coders and ink roller coders print the same message with movable metal type, so they cannot print a QR code at all.

You need a thermal inkjet (TIJ) printer. TIJ printers build the code dot by dot from a digital file, so every package can carry a different code. The [A5 handheld TIJ printer](/products/a5-handheld-inkjet-printer/) prints QR codes, barcodes (Code 128, UPC, EAN, Code 39), text, dates and serial numbers at 300–600 dpi, with a print height of 12.7 mm on the standard model and 25.4 mm on the S model. The [A9](/products/a9-handheld-inkjet-printer/) does the same with a larger 5-inch touchscreen, and the [P500](/products/p500-handheld-inkjet-printer/) uses two print heads for a 25.4 mm print height in one pass. For a production line, the [T10-2 online printer](/products/t10-2-online-inkjet-printer/) prints QR codes up to 25.4 mm high as products pass a sensor, and the [K80 conveyor printer](/products/k80-conveyor-inkjet-printer/) does the same over a belt.

Resolution matters more than it does for plain text. A date printed at low resolution is still readable; a QR code printed at low resolution has blurred module edges, and the scanner has to guess. Use the highest resolution your printer offers for QR work — 600 dpi when the model supports it — and test the result before you commit to a run.

## Size: how small is too small?

A QR code is made of modules — the small squares that make up the pattern. The scanner needs to see each module clearly, and it needs a clear border around the whole code, called the quiet zone, of at least four modules on every side.

Three practical rules:

- **Never print a QR code smaller than about 20 × 20 mm.** Below that, even a good printer struggles to keep the modules distinct, and cheap phone cameras cannot resolve them. If the code carries a long URL or a lot of data, it has more modules and needs to be bigger — a dense code at 20 mm is far harder to scan than a short code at the same size.
- **Keep the data short.** A QR code that points to a short link scans more reliably than one carrying a paragraph of text. Use a short URL, and put the detail on the landing page, not in the code.
- **Match the code height to the print head.** A single 12.7 mm head prints a code up to 12.7 mm tall — too small for most QR codes. For a 20–25 mm code you need a 25.4 mm head, such as the A5S, A9S or K80S models, or a two-head machine like the P500 or T10-2. Check the print height before you buy, not after.

## Contrast and ink: the surface decides

A scanner reads contrast, not colour. Black ink on a light surface is the safest combination, and it is what the ISO print-quality standard is graded against. White, red or blue ink can work on a dark surface, but test it — coloured ink on a coloured carton is the most common cause of codes that scan in the office and fail in the warehouse.

The ink type must match the surface, or the code smudges before it is scanned:

- **Cartons and paper:** water-based ink is fine. It dries fast on porous surfaces and gives sharp edges.
- **Plastic bags, film, glass and metal:** use a solvent quick-dry ink. Water-based ink beads or wipes off these surfaces. Our [TIJ ink cartridge guide](/blog/tij-ink-cartridge-guide/) explains the 12.7 mm and 25.4 mm cartridge options and which ink fits which surface.
- **Curved surfaces (bottles, cans, jars):** print on the flattest area you can find, keep the code small enough that the curve does not distort the far edge, and check the scan at the angle a customer would actually hold the bottle. Our guide to [printing batch codes on bottles](/blog/how-to-print-batch-codes-on-bottles/) covers the surface problems in detail.

Keep the print distance right, too. TIJ printers work best at 2–5 mm from the surface. Too far and the dots spread and blur; too close and the head can smear wet ink. If the code looks fuzzy at the edges, the distance is the first thing to check.

## Test every code before the run ships

Never trust a code that has only been checked on screen. Print a sample on the real packaging, with the real ink, and test it properly:

1. **Scan it with three different phones** — a recent phone, an older phone, and a cheap one. If it only scans on the good phone, it will fail for customers.
2. **Scan it at arm's length and in poor light.** A code that only scans at 10 cm in bright light is a code that will fail in a shop or warehouse.
3. **Scan it after handling.** Rub the printed carton, stack it, ship a sample. If the code smudges or scratches off, the ink is wrong for the surface.
4. **Scan it from the angle it will be read at** — flat on a shelf, upright on a bottle, or moving on a conveyor.
5. **Check the quiet zone.** No text, logos or box edges inside the four-module border around the code. A design that crowds the code is the easiest mistake to make and the easiest to fix.

If you print a different code on every pack — serial numbers or one-item-one-code traceability — scan a sample from the start, middle and end of the run. A head that starts clean and degrades as it warms up will produce codes that pass at 9 a.m. and fail by noon.

## Common QR printing mistakes

- **Printing the code too small** to fit the design, instead of sizing the design around the code.
- **Using a 12.7 mm head for a 25 mm code** and splitting the code across two passes.
- **Water-based ink on plastic or glass**, so the code wipes off in handling.
- **No quiet zone** — text or a border touching the code.
- **Printing on a curved or wrinkled surface**, such as a slack film bag, where the modules distort.
- **Never testing with a real phone** before the full run.
